## 1. ❓ WHAT (Core Identity & Deliverable)
**AttendSmartly** is an open-source, student-focused Android mobile application designed to simplify academic attendance tracking. Unlike basic counters, it combines:
- Weekly timetable scheduling with room numbers, instructor tags, and recurring patterns.
- **Extra Class & Rescheduling Engine**: Schedule one-off extra lectures on any date, or reschedule existing classes with reason metadata and instant revert capability.
- Customizable attendance unit rules per class (e.g. 2-hour lecture = 2 units, 2-hour lab = 1 unit).
- Real-time mathematical calculation of **Safe Bunks** and **Recovery Classes** with floating-point precision tolerance.
- Smart OCR timetable image scanner powered by Google Gemini Vision API.
- Modular Sub-Window Settings (Attendance Rules with preset chips, Notifications, Appearance, AI OCR, Data Management, About & Updates).
- Customizable class notification settings (sound, vibration, runtime permission handling) and background reminder alarms.
- Offline JSON backup export/import with 100% roundtrip fidelity and SAF-based CSV report generation.

---

## 2. 🎯 WHY (Problem Statement & Value Proposition)
Most universities enforce strict attendance minimums (typically 75% or 80%) with heavy penalties (debarment from final examinations). Existing attendance apps fail because:
1. **Uniform Class Fallacy**: They treat every class as equal (1 hour), failing to account for multi-hour practical labs that carry different weightings.
2. **Lack of Predictive Math**: Students cannot easily answer *"Can I miss tomorrow's lecture without dropping below 75%?"* or *"How many classes must I attend to recover from illness?"*.
3. **Privacy Concerns**: Many commercial apps require invasive account registration and upload student schedules to remote servers.

**AttendSmartly** solves these issues with custom unit math, instant safe bunk calculations, and a 100% privacy-respecting offline architecture.

## 4. 📍 WHERE (Platform & Data Boundaries)
- **Runtime Platform**: Android OS versions starting from Android 7.0 Nougat (API Level 24) through Android 15+.
- **Data Boundary**: **100% On-Device Storage**. All attendance logs, timetable entries, and preferences reside strictly within local SQLite database (`attendsmartly_database.db`) and DataStore preferences. No external server tracking or remote telemetry exists.

---

## 5. ⏰ WHEN (Execution Lifecycle)
- **Real-Time Calculation**: Safe bunk and percentage metrics update instantly whenever an attendance status (Present, Absent, Cancelled) is marked.
- **Background Reminders**: Pre-class notifications trigger automatically via `AlarmManager` exact alarms and `WorkManager` background workers.
- **On-Demand OCR**: Timetable image parsing executes only when triggered explicitly by the user.

---

## 6. ⚙️ HOW (Technical Architecture)
- **Language**: Kotlin 2.0 (100% native).
- **UI & Design**: Jetpack Compose declarative UI with Material Design 3 dynamic color palette and dark mode support.
- **Architecture Pattern**: MVVM (Model-View-ViewModel) with Repository pattern and Clean Architecture separation.
- **Persistence Layer**: Room Database with KSP (Kotlin Symbol Processing) and Kotlin Coroutines `Flow` streams.
- **Asynchronous Engine**: Kotlin Coroutines & WorkManager.

---

## 7. 💰 HOW MUCH (Resource & Cost Analysis)
- **Financial Cost**: **$0.00**. Completely free and open source.
- **Device Footprint**: Compact APK payload (~15MB), negligible battery consumption, and minimal storage utilization.
- **Network Overhead**: Zero data consumption for core functionality. Optional OCR requests communicate directly with Google's API without intermediate proxy servers.
